# LUDIA Naver Bridge · v0.5.0

매장 Windows PC의 네이버 공식 로그인 세션에서 **실제로 렌더링된 예약**을 확인합니다. 신규·변경·명시적 취소를 예약번호 기준으로 반영합니다. 실계정 SmartPlace DOM·Windows 설치·휴대폰 E2E 검증은 아직 남아 있습니다. 코드 테스트를 실계정 연동 완료로 표현하지 않습니다.

## 가장 짧은 시작 순서

1. LUDIA **더보기 → 네이버 SmartPlace → PC 연결 시작**에서 ZIP을 받아 압축을 풉니다.
2. **START_NAVER_BRIDGE.cmd** 실행. Node.js가 없거나 구버전이면 공식 nodejs.org의 고정 Node 24.22.0을 SHA-256 검증 후 프로그램 폴더에 설치합니다. 시스템 PATH나 PowerShell 실행 정책을 바꾸지 않으며 관리자 권한도 필요 없습니다. x64/ARM64 Windows를 지원하도록 작성했지만 실제 Windows 실행 검증은 남아 있습니다.
3. 고정 lockfile의 Playwright 1.64.1과 공식 Chromium을 준비하고 **PC 설정 화면과 네이버 창**을 엽니다. 로그인·CAPTCHA·2FA는 원장이 네이버 공식 페이지에서 직접 처리합니다.
4. 해당 매장의 **전체 상태·취소 포함 예약 목록**으로 이동합니다. 실제 표의 열 제목으로 예약번호·날짜·시간·상태를 자동 확인하고 미리보기를 준비합니다. 자동 확인이 안 되면 **현재 예약 목록 자동 확인**, 또는 **자동 확인이 안 될 때 직접 선택**을 사용합니다.
5. 예약 미리보기와 매장·조회 기간을 확인하고 체크한 뒤 **확인하고 자동연동 시작**을 누릅니다.
6. 다음부터 START 파일을 실행하면 저장한 설정으로 시작합니다. 네이버 로그인이 만료됐을 때만 네이버 창에서 재로그인합니다. 설정을 바꿀 때는 **SETUP_NAVER_BRIDGE.cmd**를 사용합니다.

처음 실행할 때는 인터넷이 필요합니다. 설치 차단·회사 PC 정책·Windows 보안 경고가 발생하면 해당 정책을 우회하지 말고 원인을 확인하세요. 설정 화면이 안 열리면 실행 창의 이 PC 전용 주소를 여세요. 주소는 60분 한정이며 다른 사람에게 공유하지 않습니다.

## 이 PC의 LUDIA 창에 자동 반영

기본 방식입니다. **프로그램이 여는 LUDIA 창**에 바로 반영하므로 폴더를 선택할 필요가 없습니다. 앱 초기 복원과 연결 모드 확인 후 데이터를 전달하며, 앱 저장 성공 응답을 받아야 정상 반영으로 표시합니다. 약 60초마다 확인합니다.

이 창은 프로그램의 전용 브라우저 프로필을 사용합니다. **기존 일반 Chrome/Edge·다른 PC·휴대폰의 데이터와 별도**입니다. 기존 자료는 앱의 백업/복원을 사용하며, 프로그램이 임의로 기존 브라우저 데이터를 가져오거나 삭제하지 않습니다. 프로그램 폴더/프로필을 지우면 기기 데이터가 유실될 수 있으므로 앱 백업을 보관하세요.

검증된 JSON도 exports 폴더에 남겨 기존 **PC 폴더 연결** 방식을 유지합니다. 고급 설정의 openLocalApp=false는 기존 폴더 방식만 사용합니다. 설정 UI에서 저장하면 기본값인 직접 반영 방식으로 돌아옵니다. 비밀번호·쿠키·고객 원문은 앱 전달 JSON에 넣지 않습니다.

## 취소가 별도 목록에 있을 때

기본 목록에 취소가 함께 표시되면 추가 설정이 필요 없습니다. 취소가 별도 상태 필터에만 보이면 다음과 같이 확인합니다.

1. 기본 목록의 미리보기를 먼저 확인합니다.
2. 네이버 창에서 같은 매장의 취소 목록으로 이동합니다.
3. 설정의 **취소가 다른 목록에 있을 때 → 현재 취소·추가 목록도 연결**을 누릅니다.
4. 추가 미리보기까지 확인하고 최종 확인 체크 후 연결합니다.

추가 목록은 최대 4개이며, 같은 예약관리 path·fragment와 매장 식별 query를 유지하고 확인한 상태/날짜 query만 달라야 합니다. URL 없이 상태만 바뀌는 화면, 다른 path, 다른 형식의 불확실한 목록은 자동 연결하지 않습니다. 실제 예약 한 건 이상을 읽어 확인해야 합니다. **설정을 다시 저장할 때 추가 목록도 재확인하세요.**

각 목록은 별도 탭에서 확인하고 함께 판정합니다. 어느 목록이든 로그인 만료·잘못된 항목·새로고침 실패가 있으면 그 회차를 정상 Sync로 표시하지 않습니다. 같은 예약번호에 모순된 내용이 있으면 추측해 고르지 않습니다. 목록에서 사라진 예약은 취소로 간주하지 않습니다.

## 신규·변경·취소와 충돌

- 예약번호 하나는 예약 하나로 유지합니다. 변경·취소·재확정 및 재전송으로 중복 예약을 만들지 않습니다.
- 같은 담당자끼리 시간이 겹칠 때만 보류합니다. 원장과 직원의 동시시술은 허용합니다.
- PC 반영은 최종 슬롯을 함께 비교해 취소 후 빈 시간 사용·두 예약의 정상 시간 교환을 처리합니다. 보류한 변경은 기존 일정을 유지하고 이후 회차에 재검사합니다.
- 서버 전송은 취소·노쇼를 먼저 보내 같은 배치의 이동이 해제 전 슬롯에 걸리지 않게 합니다. 서버의 실제 충돌은 기존 관리자 검토 흐름을 유지합니다. 서버에서 두 예약을 원자적으로 맞교환하는 기능은 이번 변경 범위가 아닙니다.
- 가격·사진견적 연결·원장 메모를 덮어쓰지 않습니다. 시술·담당자는 화면의 명시적 필드와 등록된 기준으로만 처리하며 미확인 값은 추측하지 않습니다.
- 상태 전이는 먼저 디스크 outbox에 저장하고, 정확한 저장 응답 이후 확정합니다. 재시작·전송 실패·A→B→A 전이에도 미확인 이벤트를 보존합니다.

## 서버 전송 · 휴대폰 확인

기존 Vercel/Supabase 연결을 사용합니다. 필요한 서버 설정은 SUPABASE_URL, SUPABASE_SECRET_KEY(또는 service role), LUDIA_SALON_ID, LUDIA_SYNC_TOKEN, 실제 매장 row 및 기존 ludia_ingest_naver_bridge_event RPC입니다. **서버 준비가 안 되면 이 방식으로 시작하지 않습니다.** 현재 운영 서버의 준비 상태는 앱에서 확인합니다.

PC에는 별도의 동기화 키만 입력하고 Supabase 서버 키나 네이버 비밀번호를 넣지 않습니다. 서버 연결 검사는 예약·연결 상태를 쓰지 않는 읽기 전용 검사입니다. 휴대폰 조회의 외부 연동 관리자 키는 동기화 키와 다르며 서버에서 한 매장으로 제한합니다. 일반 LUDIA 기능에는 로그인을 요구하지 않습니다.

서버 예약의 시술/담당자 UUID는 기존 매장 매핑과 정확한 전화번호 매칭을 사용합니다. 화면의 표시 이름만으로 임의 배정하지 않습니다. 현재 운영의 서버 설정·실제 매장/RPC·키와 신규/변경/취소 DB 반영 및 휴대폰 조회 검증이 남아 있습니다.

## 범위와 보안

- **확인한 기간·페이지의 렌더링된 예약만** 수집합니다. 전체 날짜 자동 순회·페이지 넘김·가상 스크롤 전체 로딩은 지원하지 않습니다.
- 이 연결은 **네이버 → LUDIA 단방향**입니다. LUDIA 수기 예약으로 네이버 시간을 자동 차단하거나 네이버 예약을 생성/취소하지 않습니다.
- 첨부사진·리뷰는 수집하지 않습니다. 사진 견적은 기존 앱 업로드 경로를 사용합니다.
- broad selector나 원문 추측을 사용하지 않습니다. 자동 항목 확인은 실제 table의 명시적 열 제목이 유일할 때만 후보를 만들고, 모든 행의 파싱과 원장 확인을 거칩니다. 미확인 SmartPlace selector는 배포하지 않습니다.
- 설정 서버는 127.0.0.1 임의 포트·난수 capability·60분 만료·Origin/Host 검사·self-only CSP로 보호합니다. 설정 응답과 진단에는 키·비밀번호·쿠키·고객 원문을 넣지 않습니다. 입력으로 PC 파일 경로를 변경하지 못합니다.
- 앱 전달은 전용 브라우저의 공식 LUDIA origin에서만 수행합니다. 새로운 공개 로컬 API/CORS 포트를 만들지 않습니다. PC 연결과 서버 연결 상태를 구분하며 최근 성공이 없으면 연결됨으로 표시하지 않습니다.
- config.local.json, .naver-profile, .bridge-state.json, .bridge-local-state.json, exports는 외부에 공유하지 않습니다. 깨진 설정/상태는 빈 값으로 덮어쓰지 않습니다.

고객정보 없는 진단 파일: 설정 화면의 버튼 또는 npm run diagnose.
다운로드 빌드: python3 scripts/build-bridge-package.py. 명시적 allowlist의 소스/예제만 포함하며 실제 설정·키·프로필·예약·실행 환경·node_modules는 제외합니다.
